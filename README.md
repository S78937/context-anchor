# Context Anchor ｜ AI 会忘事，所以我给它写了张纸条

**一句话**：把长任务里"你说过但 AI 已经忘了"的硬性要求，存成一张几十字的接续记录；换会话时带上它，AI 就能逐项核对，而不是从零猜。

**60 秒可交互 Demo（不用装任何东西）**：<https://S78937.github.io/context-anchor/demo.html>

也可以把仓库里的 `demo.html` 下载下来直接双击打开——单文件、零依赖、不联网也能跑。

```
# 入门指南 | v1
目标：制作新手指南。来源：本轮U1—U2；U数字=用户消息。
要求：R1 中文；R2 三章 [U1]；R3 不含编程；R4 交付Markdown，不要PDF [U2]。
状态：助手声称已完成，未提供产物，尚未核实。
下一步：如有成稿先核对，否则起草。未授权发布。
```

上面这六行，就是一个任务全部的"记忆"。存成一个普通文件（默认在项目里的 `.context-anchor/<任务名>.md`）。

**为什么需要它**：AI 的上下文窗口是一块有限大小的滚动条。早期说过的要求、后来的修正、已经作废的旧方案，全都混在一条时间线上往下滑，滑出窗口就等于不存在——模型并不知道自己"忘了"，它只是看不到那些字了。Context Anchor 不指望模型一直记着，而是让它把该记的**写下来**。

## 三步跑起来

1. **装**：下载 [v0.2 Release](https://github.com/S78937/context-anchor/releases/tag/v0.2)，把 `context-anchor` 文件夹放进宿主的 Skill 目录（`~/.codex/skills/context-anchor/` 或 `~/.openclaw/skills/context-anchor/`）。
2. **存**：在当前对话说 ——
   > 使用 context-anchor：把当前任务的目标、硬性要求、我后来的修正和未完成事项整理成接续记录。有文件工具时保存到当前任务目录，否则给我可复制版本。
3. **恢复**：**新开**一个对话，把记录贴给它，说 ——
   > 使用 context-anchor：读取这份接续记录，核对仍有效的要求，接着完成下一步。

需要同时提供记录文件或可读取的路径；**仅仅新开聊天不会自动带入旧上下文**——它是个文件，不是魔法。

## 它到底做了什么

- **提取与去重**：只收录当前任务的有效要求；用户明确修改只替换对应条目，其他条件保留；否定、例外、条件分支、精确数字和指定原文不能在压缩时省略。
- **保留来源**：每条要求带稳定 ID（R1…）和来源标记（如 U18）。不能只写"按 U2 改"——新会话可能没有 U2 的原文。
- **区分完成与声称完成**：没有产物证据的"已完成"压成一句"声称完成，未核实"。
- **控制长度**：一般任务 300–600 个中文字参考，优先删重复而不是删要求。
- **不碰敏感信息**：不保存密钥、令牌或无关个人信息。

## 验证结果

2026-10-16：精简版使用**两段各 211 条消息**、合计 31,455 个 Unicode 字符的虚构长对话测试。普通提示、原版 Skill、精简版**各单次生成**记录，随后**新会话仅凭记录恢复**成稿。

| | 普通提示 | 原版 | 精简版 (v0.2) |
|---|---|---|---|
| 记录长度 | 1513 字符 | 3221 字符 | **1542 字符** |
| 48 项预设约束（记录阶段） | 48/48 | 48/48 | **48/48** |
| 48 项预设约束（恢复阶段） | 48/48 | 48/48 | **48/48** |

- 精简版比原版**缩短 52.1%**，比普通提示多 1.9%；这不是 Token 或费用统计。
- **本轮未观察到精简版相对普通提示的准确率增益。** 样本小，主助手评分，非独立人工盲审；OpenClaw 原生安装、上下文上限、多次稳定性和真实用户收益未验证。
- 完整输入、版本快照、12 份输出和逐项评分见 [长对话测试报告](reports/v0.2/长对话测试报告.md)，也可在 [v0.2 Release](https://github.com/S78937/context-anchor/releases/tag/v0.2) 下载原始证据包。

## 它不做什么

它帮助降低遗漏，**不是**模型长期记忆插件；不能扩展上下文窗口、恢复没有提供的聊天历史，或保证 AI 永远不忘。**没有后台服务、API 调用、遥测或自动同步。**

## 手动验收场景

`EVALUATION.md` 列了 12 类手动行为验收场景：用户修正、未确认建议、旧任务混入、缺少证据、无文件工具、写入失败、并发更新、来源指令注入、跨任务记录、丢失材料、敏感字段、长约束清单。**结构校验与文档场景检查不是实际模型成功率测试**，也没有伪造跨客户端测试或准确率数据。

## 兼容性

已检查 Skill 结构并完成两段长对话的三组接续测试。**尚未在 OpenClaw 原生环境安装验证**，不承诺所有平台即装即用。格式支持不等于工具、权限和触发方式完全一致。

## 文件说明

- `SKILL.md`：Skill 主入口
- `references/checkpoint-template.md`：记录格式
- `references/example.md`：虚构的用户修正示例
- `EVALUATION.md`：手动行为验收场景与已完成检查
- `TEST_RESULTS.md`：本轮测试结果及限制
- `reports/v0.2/`：完整测试报告、协议、评分表、原始输入输出与 SHA256 清单
- `demo.html`：单文件可交互演示，双击即可打开

## 记录与隐私

真实接续记录应存放在使用者的任务目录，默认 `.context-anchor/<task-id>.md`，不放在 Skill 安装目录。`.gitignore` 已排除默认记录目录及常见本地秘密文件，但忽略规则不作用于已被 Git 跟踪的文件，也不覆盖任意命名的自定义记录——**公开前请检查所有待上传文件，真实聊天、路径和密钥不要放入示例**。
